# 紫微斗数独立排盘工具

这是一个独立的静态网页模块，采用开源排盘库 [iztro](https://github.com/SylarLong/iztro) 生成紫微斗数命盘。

## 使用
- 在 GitHub Pages 发布后打开本目录的网页。
- 选择性别、出生日期、时辰和公历/农历后，点击“生成命盘”。
- 可展开原始命盘 JSON、导出 JSON 或打印为 PDF。

## 当前版本说明
- 纯前端静态网页，不需要自建服务器或 API Key。
- 通过 esm.sh 加载 iztro，因此首次排盘需要网络连接。
- 已加入真太阳时校正：输入出生地当地准确时间、经度和出生当日 UTC 偏移后，网页会按经度差与均时差计算校正时间，并按校正后的日期/时辰调用排盘引擎。
- 经度可从地图或可靠地理资料查询后手动填入；纬度仅供记录/后续扩展，目前公式不使用纬度。地点文本不会自动解析为坐标。
- 历史夏令时、历史时区变更不会自动识别，必须选择出生当日实际 UTC 偏移。农历日期模式暂不自动校正真太阳时；建议先以公历出生日期和当地时间校正。
- 闰月、晚子时等排盘口径可能因流派而异，正式使用前建议用已知命例进行交叉核验。

## 真太阳时校正说明
- 采用近似均时差公式，校正量 = 4 ×（出生地经度 − 15 × UTC 偏移小时）分钟 + 均时差。
- 校正后会显示真太阳时、经度修正和均时差，并把校正后的日期及对应时辰交给排盘引擎。
- 这是一种常用近似算法，不能代替历史时区数据库；出生时间靠近时辰交界时，建议同时核对相邻时辰。

## 晚子时与闰月口径（2026-10 更新）
页面已增加可切换规则，默认采用本工具当前建议的口径：
- **晚子时默认按次日换日**：23:00–23:59 的排盘日期向后顺延一天，时辰按子时处理；可切换为保留当日。此项是可配置的流派口径，不代表存在所有流派公认的唯一答案。
- **闰月默认整月归下月**：输入闰月时，把该月按下一个普通农历月处理；另提供“初一至十五归前月、十六以后归下月”（调用 iztro 的分界处理）、“整月归前月”和“按闰月本月处理”选项。
- 闰月规则只在历法选择为“农历”且勾选“闰月”时应用。公历模式不受闰月选项影响。
- 农历闰月转规则口径后，如果目标月份不存在用户输入的日期（例如 30 日），排盘引擎可能报错；此时应核对该目标农历月的实际天数，不要自行假定日期有效。
- 这些设置让程序按指定规则计算，不等于证明某种规则对人生预测更准确。建议用固定边界案例（22:59、23:00、23:30、00:00；闰月初一、十五、十六、月末）和可信排盘结果交叉验证。

参考 iztro 参数说明：byLunar 的 fixLeap=true 对应闰月前半月归前月、后半月归下月；本工具的“整月归下月”等其他选项通过转换到对应普通农历月份实现。文档：https://github.com/SylarLong/iztro-docs/blob/main/posts/astrolabe.md


## 双规则对比与规则自检（2026-10 更新）
- 选择“双体系对比模式”后，页面会分别计算并并排显示两份命盘：左侧使用《天纪》参考口径（晚子时按次日、闰月整月归下月）；右侧使用一组对照口径（晚子时保留当日、闰月十五分界）。
- **重要边界**：两份命盘目前共用 iztro 基础排盘引擎，真正独立的《天纪》算法尚未集成。因此这是“规则组合对比”，不是两套完全独立的流派算法对比；只有涉及这些规则的输入才可能出现差异，其他命例结果相同是正常的。
- 生成命盘后可点“运行规则自检”，检查日期跨月/闰年、闰月转换口径等辅助函数的固定预期结果。这是规则函数的基础回归检查，不代替真实排盘命例对照，也不能证明命理预测准确性。
- 下一阶段如要实现严格意义上的双体系，需要接入并审核另一套独立算法、明确许可证边界，并用可信命例验证命宫、身宫、五行局、十二宫与星曜位置。

## 独立算法开发记录（2026-10-29）

本次新增三个独立模块，尚未替换网页当前使用的 iztro 引擎：

- `engines/traditional-core.js`：不导入 iztro，独立实现五虎遁宫干、六十甲子纳音五行局、农历生日定位紫微、紫府定位及十四主星布列。当前输入前提是上游调用方已经提供正确的年干索引、命宫地支和农历生日；本模块尚不负责公历转农历、完整历法边界、辅煞星、大限流年及完整四化入宫。
- `engines/tianji-reference-policy.js`：单独保存《天纪》参考口径的晚子时与闰月配置。配置来源是公开第三方项目对“倪师派”的标注，不是倪海厦原始资料的完整证明；模块明确标记 `verifiedAgainstOriginalSource: false`。因此它是参考策略模块，不应称作完整《天纪》排盘算法。
- `engines/regression-suite.js`：组合基础规则自检、口径边界测试及穷举检查。当前本地执行结果为 **299/299 通过**：传统核心规则 12/12、《天纪》参考口径边界 5/5，以及 282 项穷举结构检查。

紫微定位公式还与公开资料中的五种五行局、每局 30 个农历生日位置表进行了逐项交叉核对，150/150 项一致。该交叉核对用于检查安星公式实现，不代表所有流派规则已统一，也不代表命理预测准确性得到验证。
