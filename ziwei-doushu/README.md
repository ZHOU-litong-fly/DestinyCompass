# 紫微斗数独立排盘工具

这是一个静态网页模块，包含《天纪》规则实验引擎与通用传统独立实验引擎，两套核心排星算法分别实现，不调用 iztro。

## 使用
- 在 GitHub Pages 发布后打开本目录的网页。
- 选择性别、出生日期、时辰和公历/农历后，点击“生成命盘”。
- 可展开原始命盘 JSON、导出 JSON 或打印为 PDF。

## 当前版本说明
- 纯前端静态网页，不需要自建服务器或 API Key。
- 两套独立核心引擎均通过项目内 JavaScript 模块执行；公历/农历转换通过 esm.sh 加载 lunar-javascript，因此首次排盘需要网络连接。
- 已加入真太阳时校正：输入出生地当地准确时间、经度和出生当日 UTC 偏移后，网页会按经度差与均时差计算校正时间，并按校正后的日期/时辰调用排盘引擎。
- 经度可从地图或可靠地理资料查询后手动填入；纬度仅供记录/后续扩展，目前公式不使用纬度。地点文本不会自动解析为坐标。
- 历史夏令时、历史时区变更不会自动识别，必须选择出生当日实际 UTC 偏移。农历日期模式暂不自动校正真太阳时；建议先以公历出生日期和当地时间校正。
- 闰月、晚子时等排盘口径可能因流派而异，正式使用前建议用已知命例进行交叉核验。

## 当前双引擎状态（2026-10-29）

页面已接入三种模式：
- **《天纪》规则实验模式**：使用 `tianji-engine.js`，独立实现公开《天机道》文本中可核对的命身宫、五行局、紫微/天府、十四主星与已实现辅煞星规则。
- **通用传统模式**：使用 `traditional-chart.js` 与传统核心模块独立组装命盘。
- **双引擎对比模式**：左侧为《天纪》规则实验盘，右侧为通用传统独立实验盘，两侧不共享核心排星算法。

重要限制：《天纪》部分辅煞星、四化与晚子时口径仍需原始资料逐条核实；两套引擎都仍需更多标准命例逐盘验盘，不能把结构测试通过理解为预测准确性已验证。

## 真太阳时校正说明
- 采用近似均时差公式，校正量 = 4 ×（出生地经度 − 15 × UTC 偏移小时）分钟 + 均时差。
- 校正后会显示真太阳时、经度修正和均时差，并把校正后的日期及对应时辰交给排盘引擎。
- 这是一种常用近似算法，不能代替历史时区数据库；出生时间靠近时辰交界时，建议同时核对相邻时辰。

## 晚子时与闰月口径（2026-10 更新）
页面已增加可切换规则，默认采用本工具当前建议的口径：
- **晚子时默认按次日换日**：23:00–23:59 的排盘日期向后顺延一天，时辰按子时处理；可切换为保留当日。此项是可配置的流派口径，不代表存在所有流派公认的唯一答案。
- **闰月默认整月归下月**：输入闰月时，把该月按下一个普通农历月处理；另提供“初一至十五归前月、十六以后归下月”（调用 iztro 的分界处理）、“整月归前月”和“按闰月本月处理”选项。
- 闰月规则只在历法选择为“农历”且勾选“闰月”时应用。公历模式不受闰月选项影响。
- 农历闰月转规则口径后，如果目标月份不存在用户输入的日期（例如 30 日），排盘引擎可能报错；此时应核对该目标农历月的实际天数，不要自行假定日期有效。
- 这些设置让程序按指定规则计算，不等于证明某种规则对人生预测更准确。建议用固定边界案例（22:59、23:00、23:30、00:00；闰月初一、十五、十六、月末）和可信排盘结果交叉验证。

参考 iztro 参数说明：byLunar 的 fixLeap=true 对应闰月前半月归前月、后半月归下月；本工具的“整月归下月”等其他选项通过转换到对应普通农历月份实现。文档：https://github.com/SylarLong/iztro-docs/blob/main/posts/astrolabe.md

## 独立算法开发记录（2026-10-29）

已建立并接入以下模块：

- `engines/core-rules.js`：天干地支、十二宫、四化表与基础规则。
- `engines/traditional-core.js`：五虎遁宫干、命宫/身宫、纳音五行局、紫微/天府定位及十四主星布列。
- `engines/auxiliary-stars.js`：左辅右弼、文昌文曲、禄存擎羊陀罗、天魁天钺、天马、地空地劫、火星铃星等十四颗辅煞星的基础定位。
- `engines/traditional-chart.js`：将独立核心规则、十四主星、已实现辅煞星、十二宫宫干与年干四化标注组装成结构化命盘。
- `engines/calendar-layer.js`：通过 `lunar-javascript` 完成公历/农历转换、闰月有效性校验与晚子时日期策略处理；历史时区/DST 和真太阳时仍由网页输入层负责。
- `engines/standard-cases.js`：新增可复算标准案例，参考 iztro 公开的 2023-01-22 与 2023-02-19 命宫/身宫边界测试。
- `engines/tianji-engine.js`：独立实现公开《天机道》文本中可核对的核心公式；不导入通用传统核心模块或 iztro。其部分辅煞星、四化与晚子时规则仍待原始资料逐条核验。
- `engines/tianji-reference-policy.js`：保存《天纪》参考口径，明确标记 `verifiedAgainstOriginalSource: false`。
- `engines/regression-suite.js`：组合模块级测试、固定紫微定位参考表与穷举边界检查。

现有传统模块回归套件执行结果为 **1028/1028 通过**（传统核心规则 14/14、《天纪》参考口径 5/5、辅星基础定位 15/15、独立传统命盘组装 8/8、穷举检查 986/986）。另外，历法层自检 6/6 通过；网页新增的公开历法参考案例和标准案例套件需要在浏览器中加载 `lunar-javascript` 后执行，因此本次静态检查没有把它们计入上述 1028 项。

150 个紫微星定位参考值（五种五行局 × 30 个农历生日）与公开参考表一致。该结果验证的是定位公式/参考表的一致性，不代表所有流派规则统一或预测准确性得到证明。
